# Review of every helper (2026-11-10)

This is a full logic review of all 35 helpers, done by reading the code. The comparison with other addons is in
`compare_2026-11-10.md`.

**How it was done:**
- Four reviewers each read a group of helpers. Three finished; the first round of five stopped on a usage limit
  before reporting.
- Every finding below was checked against the code before it was fixed.
- Each fixed bug has a test that fails on the old code and passes on the new one, except where a row says
  otherwise.
- All tests pass (`tests\runall.ps1`).

## Checked and kept, with the reason

- **`UISpecialFrames` (ForeverHub, ForeverHelper)**
  - We add our window names to this Blizzard table so ESC closes our windows.
  - It's Blizzard's documented way for addons to do this, and it's listed in `taint_audit.md`.
  - The alternative, catching ESC ourselves, needs `SetPropagateKeyboardInput`, which can't be changed in combat.
    A window opened in combat would then swallow every key.
  - Kept. If an ESC-in-combat "blocked action" error ever shows on the Errors page, revisit.
- **`seterrorhandler` (!ErrorLog)**
  - The error page needs it, as BugGrabber does. It's listed in `taint_audit.md`.
  - Kept.

## Found, not fixed (low value or needs an in-game check)

- **MapPins, 120-pin world-map cap:** the cap fills layer by layer, so in a zone with many saved places, deaths
  and rares can be cut. A fair share per layer would fix it.
- **MapPins:** builds one small string per frame while the world map is open to spot changes. This is a
  performance nit.
- **MapPins:** the minimap edge margin assumes 14 px icons, but guide icons are 15 px, so they can poke half a
  pixel past the edge.
- **QuestTracker:** found clean. Layout changes wait for combat to end, and folding and dragging check for combat.
